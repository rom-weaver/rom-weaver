# nod patch queue

The manifest uses upstream ebd80cac99b48a323200d84365e07a58cc27412d, not a newer release or the former fork marker. Archive extraction is normalized to `nod/src`; `source.extraFiles` copies both licenses from the same verified archive.

Patches 0001–0012 isolate portable changes: DOL/FST bounds, Wii FST alignment, absolute Wii partition end, preloader depth/cache capacity, GCZ geometry, NFS sparse sectors, bzip2 full-output fallback, block options, empty-window query, tracing and CISO block size validation. Patches 0013–0014 isolate Rust codec and WASI path adapters. Patches 0015–0020 inline the library, one concern each: Python binding removal, lib.rs→mod.rs and path rewrites, workspace rustfmt, lint allowances, dead-code cleanup, and test hooks (including inline WIA coverage). Patch 0017 is formatting only. No upstream upgrade is introduced; the CISO block size check is the only source behavior added after the original queue.

PR statuses reflect the public upstream audit dated 2026-10-15. `no-submission-found` means that audit found no matching public submission; repository/file URLs provide context, not a claim of submission. `related-open` for codec migration identifies the related PR rather than claiming this patch is its exact content. The bzip2 fallback exists in later upstream source but differs from this pinned baseline. The pinned baseline already includes GameCube FST loading, so no duplicate patch is necessary. Existing tests listed per patch are related checks, not a claim that this queue-generation task ran the behavioral suite.

Manifest test filters use the native library test module paths. The DOL command checks normal DOL/FST extraction; there is no dedicated hostile DOL bounds test in that module. The preloader command checks threaded byte parity, not its read-ahead depth/cache sizing. Block-options, Window::is_empty and tracing patches list the broader nod library tests because no dedicated regression test was identified. WASI path resolution needs the listed WASM build and runtime coverage beyond the native I/O tests. GCZ, NFS and CISO submission status is `unverified`: these deltas were identified after the supplied public-submission audit. Other absence statuses mean only that the bounded public audit found no matching submission.
